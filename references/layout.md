# 模板结构与 CAD 材料表识别规则

本文件供需要调整解析规则或更换设计院图框时查阅。首次使用只要 `inspect` 结果正确，
无需改动这里的任何参数。

## 1. 两套模板与列定义

| 模板（`--template`） | 文件 | 工作表 | 明细容量 | 定位 |
|---|---|---|---|---|
| `summary`（默认） | `材料汇总模板-加强比对版.xls` | 9 张 | 第 4～118 行（115 行） | 空白加强比对版，新项目生产用；含 `2-汇总`、新旧打印版、`5-变更估价`、`@变更单EXCEL模板`、`调拨价` |
| `sample` | `材料平差模板.xls` | 10 张 | 第 4～43 行（40 行） | IC24H201 成品文件，另含 `广联达导入`、`206-变更单打印`；用于复现与逐格验收 |

两份模板的 `1-初步比对` 表头与列含义完全一致，第 3 行是空行（A3=0），
第 1～2 行是两层表头。模板容量由 O 列比对公式的最后一行自动探测
（成品 43 / 加强版 118），脚本中不写死行数。

| 列 | 含义 | 本技能是否写入 |
|---|---|---|
| A | 编号 1..N | 是 |
| B | 标记（分组标题行写 2，「不用入物资系统材料：」除外） | 是 |
| C | 竣工图-物料描述 | 是 |
| D | 竣工图-单位 | 是 |
| E | 竣工图-数量 | 是 |
| F/G/H | 材料平差：领量 / 退量 / 平差 | 否，保持模板原值或公式 |
| I | 标记（同 B） | 是 |
| J | 施工图-物料描述 | 是 |
| K | 施工图-单位 | 是 |
| L | 施工图-数量 | 是 |
| M/N | 领量 / 退量（占位） | 否 |
| O | 异同，公式 `=IF(C4=J4,"相同","")` | 否，保留公式自动重算 |

分组标题行（无单位、无数量、描述以「：」结尾）示例：
`配套中压地下材料：`、`不用入物资系统材料：`、`中压地上部分：`、`配套地上部分：`。

写入前只清空 `A4:E{末行}` 与 `I4:L{末行}`（末行 = max(写入行数, 模板容量)）；
输出行数超过模板容量时，用 `Range("O{容量}:O{last}").FillDown()` 把 O 列公式补到新增行。

### `2-汇总` 同步映射

`2-汇总` 与 `1-初步比对` 之间**没有跨表公式**，C/D/E/I 是人工「变更复制区」。
本技能按成品文件的实际填法自动同步，只动这四列：

| `2-汇总` 列 | 含义 | 来源 / 处理 |
|---|---|---|
| A | 编号 | 沿用模板预置编号，不写（打印版 VLOOKUP 依赖完整编号列） |
| B | 标记 | 不动 |
| C / D / E | 物料描述 / 单位 / 竣工数量 | 取 `1-初步比对` 的 C / D / E |
| F / G | 领量 / 退量 | 不动，由施工单位后续填报 |
| I | 施工图数量 | 取 `1-初步比对` 的 L（竣工独有项留空） |
| H / J / K / L / M / N | 平差 / 变量 / 增加材料 / 减少材料 | 模板公式，自动重算；行数超容量时 FillDown 扩展 |

下游 `4-汇总打印版 (新版)` 用 `VLOOKUP($A5,'2-汇总'!$A:$N,...)` 取数，
`5-变更估价` 同样引用 `2-汇总`，因此四列填入后整本汇总表即联动。
若模板的 C/D/E/I 首行是公式（而非空白常量），脚本跳过同步以免破坏模板。
`--no-fill-summary` 可完全关闭这一步。

## 2. CAD 图纸里的材料表长什么样

样例（IC24H201 南昌县向塘博乐美幼儿园）中，一份 DWG 会同时出现多张表：

| 图纸 | 表 | 阶段标注 | 有效行 |
|---|---|---|---|
| 竣工图 | `燃气管道布置图、材料表`（图签写「竣工图」） | 竣工图 | 40（分上下两段续表：29 + 11） |
| 竣工图 | 3 页 `工艺设备材料表` | 施工图 | 29 + 6 + 17 |
| 施工图 | 3 页 `工艺设备材料表` | 施工图 | 29 + 6 + 17 |

因此**不能简单地把 DWG 里第一张表当作该图的材料表**：竣工图 DWG 里
「竣工图」阶段的表才是竣工材料表，其余三页是随图附带的施工图版本
（编制竣工图时保留下来的旧表，**不参与施工图数量**，见 4.1「施工图数据源」）。
施工图第 3 页是户内材料（DN25 波纹软管、超声波表、探测器等），
成品模板中没有对应行，匹配后被列为「施工图多出」，不写入表格。

材料表不是 AutoCAD TABLE 对象，而是由 `LINE` 网格加独立 `TEXT/MTEXT` 文字构成。
表头一行文字（含居中用的空格）：

```
序号 |  物      料      描      述 | 单位 | 数量 | 标 准 号(现行) | 备  注
```

### 2026 年新图框：`名称 + 规格 + 材料` 三列表头

用户在电脑上另有 2026 年新图框（实测 `ID26B001-茶山路4号老社区民用燃气工程.dwg`），
材料表头变成两行，**没有「物料描述」表头**：

```
序号 | 标准号或图号 | 名  称 | 规  格 | 单位 | 数量 | 备  注
                        材  料 | 质量(kg)
```

`detect_tables()` 用 `NEW_LAYOUT_HEADERS`（序号/名称/单位/数量）识别，
table 标记 `layout="name-spec"`；`_column_bounds()` 按新列序定界。

**描述拼接（v1.7.0 修正）**：对照同图框的成品表（如
`ID26E025+新建区王记乡野人家餐饮店燃气工程.xls`）逐条核对后确认，
成品只保留「名称 + 规格」两列，**物料材质列（Q235B、KTH350-10 等）不写入**，
且名称列内部的空格/下划线原样保留，名称与规格之间用**单个空格**连接：

```
名称「热镀锌钢管_燃气专用」+ 规格「DN50（D60.3×3.8）」+ 材料「Q235B」
→ 成品：热镀锌钢管_燃气专用 DN50（D60.3×3.8）      ← 不含 _Q235B，中间是空格
```

v1.6.0 曾把三列全用 `_` 连接并吞掉空格，成品逐格比对会整列不符；v1.7.0
改为 `名称原样 + ' ' + 规格原样`。`norm_desc()` 匹配时会去掉所有空格，
因此显示格式修正不影响竣工/施工图两侧的匹配结果。
旧图框仍走 `layout="old"` 分支，逐格回归结果不变。

### 2025 起另一版图框：`名称及规格` 合并列（v1.8.0）

实测 `NC25E321-星艺装饰厨房燃气工程.dwg`（成品 21 行），表头是：

```
序号 | 标准号或图号 | 名称及规格 | （或性能等级） | 单位 | 数量 | 单总 | 备注
                        材  料   | 质量(kg)
```

**名称与规格合并成一列**，`detect_tables()` 用 `MERGED_LAYOUT_HEADERS`
（序号/名称及规格/单位/数量）识别，table 标记 `layout="merged-spec"`；
`_column_bounds()` 把名称列右界取在材质列左侧（单位锚点 − 4000×scale），
`parse_table()` 只取「名称及规格」列原样作为描述（忽略 Q235B/KTH350-10 等材料列），
拼接规则与 name-spec 相同。该图框此前检出 0 表，修正后检出 20 行、与成品逐格
竣工侧仅差成品人工补入的 1 行。

**分组标题独立成行（v1.8.0）**：数据区中无序号、无单位、无数量的标题文字
（如「厨房部分」「调压前材料：」「配合工程（长度不超过10m无外管编号）」
「厨房工程（NC25E121）」）现在识别为独立分组行（`is_header=True`），
不再拼进第一条材料描述。区分规则：位于第一条材料**之前**且括号内是纯工程编号
的文字（如「厨房工程（ID26E025）」）视为材料表大标题而忽略；位于数据区中部的
同形式文字仍是分组标题。

注意这类新图纸的施工图 DWG 可能**没有材料表**（只有图纸和设计说明），
此时输出会明确提示「施工图文件未检测到材料表，施工图数量将全部留空」，
不会挪用竣工图里残留的旧施工图表。

## 3. 解析算法与可调参数（都在 `scripts/dwg_tables.py`）

1. **表头检测**：同一 y（±320）且 x 在右方 22000 图形单位内，出现
   `序号 / 物料描述 / 单位 / 数量` 四个表头文字即认定一张表；
   每个表头列取距离本「序号」最近的匹配，避免并排多表时错配列锚点。
   表头文字归一化由 `norm_header()` 完成（去空格与全角空格、括号）。
2. **比例自适应** `_table_scale()`：`scale = (单位锚点 − 序号锚点) / 10126`。
   IC24H201 / NC25D007 图框 `scale=1.00`；ID24E107 是 1:2 缩放图框
   （锚点间距 10126 → 5063），`scale=0.50`。`_column_bounds()`、
   `_seq_entities()`、`parse_table()` 里所有固定偏移与 y 容差都乘以 scale，
   `inspect` 会打印每张表的「比例」。这是不同设计院/不同出图比例能共用一套
   参数的关键，**排查解析问题先看这个值**。
3. **阶段判定** `detect_stage()`：在表头 y ±12000×scale、表格 x 范围内找
   图签文字「竣工图」/「施工图」，取距离表头最近者。左右并排的多页常只有一页
   有图签，未标注页会继承 y 接近（<2.5 倍表宽）、x 相邻（<4 倍表宽）的
   已标注页，`inspect` 显示为「竣工图(继承)」。
4. **列边界** `_column_bounds()`：表头居中文字的插入点 x 明显右于同列数据，
   所以不用锚点中点，而用固定偏移 ×scale（下表为 scale=1 时的图形单位）：

   | 列 | 下界 | 上界 |
   |---|---|---|
   | 序号 | 序号锚点 − 1500 | 序号锚点 + 600 |
   | 物料描述 | 序号锚点 + 600 | 单位锚点 − 1500 |
   | 单位 | 单位锚点 − 1500 | 数量锚点 − 600 |
   | 数量 | 数量锚点 − 600 | 数量锚点 + 700 |
   | 标准号 | 数量锚点 + 700 | 备注锚点 − 1500 |
   | 备注 | 备注锚点 − 1500 | 表格右边界 |

   标准号/备注表头缺失时，用 `数量锚点 + 2500×scale`、`+ 2800×scale` 推算。
   **换图框时优先调这里**：先 `inspect` 看「比例」和有效行数，再用
   `extract --out rows.json` 逐行核对描述/单位/数量是否串列。
5. **页序** `detect_tables()`：表头按 y 降序、同排 x 升序编号（这是表 ID 的固定编号）。
   **拼接顺序**另由 `order_tables()` 决定（v2.1.0）：图纸无「第X页」标注时，
   ①各表序号首尾连贯（1-26 / 27-52）→ 按序号从小到大；
   ②序号从上到下（序号1在最上）→ 多表从左到右（x 升序）；
   ③序号从下到上（序号1在最下）→ 多表从右到左（x 降序）。
   走向取同组表的多数；默认并入一张成品表，仅工程编号不同才分文件。
   `--tables 2,1` 可手动覆盖自动顺序。
6. **行锚点** `_seq_entities()`：在序号列、表头 y ±42000×scale 内取所有
   1～3 位数字。`_split_segments()` 自动判断表格是自上而下还是自下而上排布，
   并在序号从 1 重新开始时切段（续表 / 新页），段边界用相邻段 y 中点切开。
7. **视觉行** `parse_table()`：文字按 y 聚类（容差 300×scale）成视觉行，
   每行按 x 归列；带序号的视觉行是记录锚点，无序号的相邻文字行
   归入 y 最近的锚点。这样既能把拆成两行的物料描述（如
   `标准楼栋调压箱_..._不锈钢箱体` + `（出口设定压力：2.5KPa）`）
   用 `\n` 合并，又不会把相邻行串进来。
8. **噪声过滤**：`SIGN_WORDS` 过滤图签文字（编 制/校 核/审 核/日 期 等），
   `_valid_unit()` 要求单位不含空格与数字且长度 ≤3，
   描述列排除纯数字，表头行整行跳过。

## 4. 匹配规则（`scripts/import_materials.py`）

- 以竣工行顺序为基准，在施工图**同分组**内按 `norm_desc()` 归一化描述精确匹配，
  命中后标记为已消耗（处理 `螺栓_M20*100` 这类在不同分组重复出现的物料）。
- 未命中的竣工行：J 写竣工描述、K 写竣工单位、L 留空——与成品模板一致。
- `--match-mode global` 忽略分组，`hybrid` 先同组再全局；默认 `group` 能复现模板。
- 分组由 `assign_groups()` 标注，跨页表格继承上一页最后的分组标题，
  因此施工图第 2 页的 6 项会自动归入「配套地上部分：」。

## 4.1 自动编排规则（`scripts/auto_export.py`）

| 环节 | 规则 |
|---|---|
| 阶段判别 | 目录/文件名含「竣工图 / 施工图」→ 材料表图签阶段（含缺图签页继承）→ 图签文字。竣工图 DWG 附带的施工图表不会让它被判成施工图 |
| 施工图数据源 | 竣工图 DWG 里残留的施工图版材料表是编制时保留的旧数据，**一律忽略**；施工图数量只取用户发送的施工图文件。仅一张竣工图时按「施工图量=竣工图量」处理 |
| 工程编号 | 文件名中的 `[A-Z]{2}\d{2}[A-Z]\d{3}` → 图签「项 目 编 号」标签右侧 → 全图正则（最后手段，可能取到通用图集号） |
| 工程名称 | 竣工图文件名中编号之后的部分（与结算文件命名一致）→ 图签「项 目 名 称」→ 文件名主干 |
| 分组 | 先按编号；无编号或「只有施工图」的组，按去掉「燃气工程/配套/低压/外管」等通用词后的核心名称相似度（≥0.4）并入有竣工图的组 |
| 输出名 | `<工程编号>+<工程名称>.xls`，非法字符替换为 `_`；同名 `-核对报告.json` |
| 单竣工图 | `design = asbuilt` 副本，J/K/L 与 C/D/E 相同，O 列「相同」，`2-汇总` 变量 0 |
| 行序 | 施工图多余项超过一半属于竣工表没有的分组 → `asbuilt`；否则 `merged`；单图固定 `asbuilt` |
| CAD 复用 | 整批只调用 `open_cad_app()` 一次，所有 DWG 共用同一 COM 实例（含重试）；`--cache-dir` 可完全离线 |
| 文件夹输入 | 目录参数递归展开成 `.dwg/.dxf` 清单（排除 `~$` 临时文件与输出目录），可多目录/文件混合；`--no-recursive` 只扫顶层 |
| 默认输出 | 拖入文件夹且未给 `--out-dir` 时，输出到该文件夹下的 `材料平差输出/` |
| 缓存时效 | `cache_is_fresh()` 要求缓存文件不早于 DWG 的修改时间，图纸改动后自动重读 |
| 脱离 AI | `run_batch.bat` 接收拖放参数，自行定位 Python、检查/安装 `pywin32`、传 `--cache-dir`、写 `run_batch.log` |

### 一张施工图含多个工程（v1.9.0）

实测 `江西师大四食堂燃气厨房.dwg`：一张施工图含 **14 张材料表、分属 13 个工程**
（商业配合 + 12 个厨房店），另有 `校审核-椿晖满园慧谷店厨房燃气工程（含配套）.dwg`
含配套/厨房两类表。实现：

1. `detect_table_project()`：材料表头 y 上方 1000~5000×scale、序号列右侧范围内，
   找以「工程」结尾的工程名文字（排除设计院名/图集名/图签标签），写入 `table["project"]`；
   `inspect` 会打印 `工程=…`。
2. `auto_export.py` 判定多工程图：图内多个工程名的核心名（去通用词后）彼此不包含；
   即使只提供 1 张竣工图也按工程名筛选对应表。同一工程的不同写法（如「XX低压燃气工程」
   与「XX燃气工程」核心名相同）不会误判。
3. `_project_match()`：只用精确/包含匹配（模糊相似度会串工程）；施工表的
   `project` 与目标竣工图名/编号匹配才取，`rows_of(..., target_project=...)` 实现。
   多张竣工图时施工图作为共享源分别提取，各生成 `<编号>+<名称>.xls`。
4. 多工程图的表紧挨着，序号搜索会跨表串扰：`detect_tables` 给表打 `multi_project`
   标，`parse_table` 只保留首行序号距本表表头 6000×scale 内的段；单工程图不设此标，
   跨页长表与 1:2 缩放图框行为不变。
5. 大图（ModelSpace > 5 万实体，实测 16 万）跳过模型空间只读布局空间，避免超时。

验收：师大配合/三米粥铺/面夫子 3 份竣工图 + 1 张多工程施工图 → 3 份成品，
每份竣工侧描述与施工侧描述 **100% 一致**（62/62、19/19、19/19）；
只给 1 张竣工图时也只取对应工程 19 行（不再混入其余 12 个工程的 279 行）；
旧三实例回归不变（IC24H201/ID24E107 0 差异、NC25D007 268 处已知人工差异）。

### 极扁表格与竣工图附带其它工程表（v2.0.0）

实测 `IE26I004-临空区金水大道（汇贤大道-瓜州路）中压改造燃气管道工程.dwg`
（run_batch.bat 生成结果曾错成 2 行超长描述、单位数量全空）：

1. **根因一：极扁表格**。该图纸材料表画在模型空间且被极度压缩：列间距「序号→单位」
   仅 128（正常约 10126，比例 0.013）、行距仅 8（正常数百）。旧代码把比例截断到下限
   0.2，列偏移放大 16 倍、行聚类容差 60 >> 行距 8，导致所有材料并成 1~2 行。
   修复：`_table_scale()` 下限降到 0.01；`_estimate_row_pitch()` 从序号列实测行距，
   `_seq_entities()` 去重与 `parse_table()` 行聚类改用 `min(原容差, pitch*0.5)`。
2. **根因二：并排表串列**。两张 name-spec 表左右并排（表头 x=23563 与 23743），
   右栏表头把左栏的「单位/数量」锚点当成自己的。修复：`detect_tables()` 在比例 <0.1
   时按 scale 收紧锚点搜索下界（`-60*sc`），正常图仍用 `-1000` 不受影响。
3. **根因三：竣工图附带其它工程表**。该竣工图内还印着「横三路-儒乐湖大街」工程的
   竣工/施工图材料表（标注了阶段），而本工程表未标注阶段。旧代码按阶段取表，取了
   别的工程的表。修复：`auto_export.rows_of()` 先按工程名筛表（本工程名/编号），
   竣工图也用本图 `name` 筛选；`keep_unmarked_project=True` 保留无工程名标注的竣工表
   （兼容 IC24H201 等老图纸），未标注阶段的表可通过工程名命中。

验收：IE26I004 从 2 行超长乱码 → **40 行**（描述/单位/数量均正确，含「不用入物资系统
材料」「废除部分材料」「其它费用」「中压埋地部分」四组），未混入「横三路」工程数据；
旧三实例回归 IC24H201/ID24E107 0 差异、NC25D007 268 处已知人工差异；
师大 13 工程样本保持（配合 62 行、三米粥铺 19、面夫子 19）。

### 无表头材料表与缓存优先（v2.2.0）

部分设计单位（实测 NC26E213 施工图）的材料表**不画表头文字**（无序号/物料
描述/单位/数量表头行），只有数据行 `标准号 | 名称 | 规格 | 材料 | 单位 | 数量`，
且左右两栏并排、序号只在左栏。`detect_tables()` 依赖表头锚点，这类图识别为 0 张。
v2.2.0 回退 `detect_headerless_tables()`：以「单位词」（米/个/台…）在多个视觉行
的同一 x 列聚类定位各栏，按相对单位列的 x 偏移还原名称/规格/数量，描述按成品
格式「名称 空格 规格」，忽略材料列。`parse_table()` 见 `headerless` 标志分流到
`parse_headerless()`。实测施工图从 0 表恢复为 27+8 行，竣工图匹配从 0 升到 25。

缓存与重读策略一并调整：缓存**优先复用**（只要能解析出表，不强制比 DWG 新），
内容校验发现坏缓存才重读；读取端自检重读最多 2 次、`load_drawing` 再重读最多 1 次
（不再叠加成 9 次）；反复 0 表时明确警告并停止、继续下一张，末尾输出
「识别结果汇总」（成功/未识别图纸清单与成品清单）。

### 批处理实时进度显示（v2.1.5）

`run_batch.bat` 旧版把 Python 输出重定向到日志、跑完才 `type` 整段，窗口长时间
空白像卡死。v2.1.5 改为：`auto_export.py` 新增 `--log-file`，用 `_Tee` 把输出
**同时**写到屏幕和日志；bat 不再重定向，进度实时可见且日志照常留档。
`main()` 分两阶段打印进度条 `[1/2] 读取图纸` / `[2/2] 生成`，每张图/每组开始
先打印 `▸ 当前项`，完成打印行式 ASCII 进度条 `progress_line()`（20 格、百分比、
已完成数，行式不用 `\r` 以便日志留痕）。实测 6 张图进度 16%→100% 递增，
日志同步 9 条进度条；括号文件名、旧三实例回归均不受影响。

### COM 读取漏实体导致缓存不完整（v2.1.4）

同一张 DWG，浩辰 COM 遍历偶发只读到部分实体（实测 NC26E213 一次 461、一次
1019；461 那份缺了竣工表区域，导致「表 0 张 / 误判施工图 / 跳过不生成」）。
坏缓存 mtime 比 DWG 新，旧逻辑会一直复用。三处加固：

1. `read_entities_com()` 读完自检：有材料表表头词却 `detect_tables()==0`，
   关闭文档重开再读，最多 3 次，取实体最多的那份；
2. 大图判据改用**文件大小 >1.5MB 或 ModelSpace.Count>50000** 跳过模型空间
   （COM Count 本身不稳，单靠它会误去遍历十几万实体而漏读）；
3. `cache_is_fresh()` 内容校验：缓存有表头词却 0 张表 → 判为不完整、强制重读；
   `load_drawing()` 读到 0 表时也删坏缓存重读（最多 3 次）。

验收：NC26E213 竣工图从「施工图 / 0 表 / 跳过」恢复为「竣工图 / 1 表 / 35 行」；
人为放入 461 坏缓存能被拦截并重读恢复；旧三实例 268/0/0、师大样本 19 行保持。

### 批处理括号文件名闪退（v2.1.3）

拖入文件名含右括号 “)” 的 DWG 时 bat 闪退，并报 “xxx.dwg was unexpected at this time”：
cmd 把文件名里的 “)” 当成 for /f 或 if (...) 命令块的结束符，而 %*（拖入参数）
在这些块内展开时触发语法错误。修复：run_batch.bat 重构为**无任何括号命令块**的结构，
全部分支改用 goto 标签；%* 只在裸命令行展开；版本提示从 for /f 改为 findstr 直出。
实测带括号文件名从 RC=255 闪退恢复为正常生成（RC=0）。bat 保持 CRLF（.gitattributes 已配置）。

### 老图纸扁表格与图签人名混入（v2.1.2）

实测 `师大南路延伸段（北京西路~省五交化工宿舍）.dwg`（2015 年图，NC15I061），
原结果只识别 1 行「毕倩如」（设计师姓名）——三处根因：

1. **物料列左界过窄**：扁表格（比例 0.01）里「物料描述」表头 x=786、实际物料 x=765、
   序号 x=761，`_column_bounds()` 用 `seq+600*scale`（仅+6）作序号列右界，
   把物料误归入序号列，只有 x≈791 的图签人名落入描述列。修复：scale<0.1 时序号列右界
   用 `seq+2`。
2. **图签人名混入物料**：扁表格里图签名（编制/校核/审核 + 人名）与最后一条材料行
   y 只差 1.5，被聚进同一行。修复：`parse_table()` 先找签名标签所在视觉 y，
   把同 y（容差 0.6，材料行距 4）的所有文字整行排除。
3. 该图 stage 标注为施工图，单竣工图规则下正常生成。

验收：师大南路从 1 行人名 → **29 行正确材料**（物料/单位/数量齐全，0 个图签人名）；
旧三实例 IC24H201/ID24E107 0 差异、NC25D007 268；IE26I004 40 行、师大样本保持。

### 多表拼接顺序规则（v2.1.0）

图纸无「第X页」标注时，`order_tables()` 决定同一成品内多张材料表的先后：
①序号连贯（1-26 / 27-52 首尾相接）→ 按序号；②序号从上到下 → 从左到右；
③序号从下到上 → 从右到左。序号走向由表内序号1的位置判断（表头在上、序号1在最上
为 top-down；序号1在最下为 bottom-up），取同组多数。检测时给每张表写入
`seq_dir` / `seq_min` / `seq_max` 字段。

验收：IE26I004 本工程两表（表2「中压埋地部分」x 较大、序号1-27；表1「废除/不用入
物资系统/其它费用」x 较小）均为 bottom-up，按「从下到上→从右到左」排为表2→表1，
成品首行由「不用入物资系统材料：」改为「中压埋地部分」，仍 40 行；
三规则单元测试通过；旧三实例 IC24H201/ID24E107 0 差异、NC25D007 268；师大样本保持。

## 5. 已知限制

- 依赖 Windows COM（CAD 与 Excel）；纯 Linux/macOS 环境需先把 DWG 转 DXF
  并改用其它 Excel 写入方案。
- 默认加强版模板容量 115 行（`2-汇总` 172 行）；超容量时 `1-初步比对` 的 O 列与
  `2-汇总` 的 H/J/K/L/M/N 公式会自动 FillDown，但 `1-初步比对` 的 F/G/H、M/N
  （领退量）不会延伸；`4-汇总打印版 (新版)` 只有约 65 行、`5-变更估价` 约 38 行，
  材料极多时需人工扩展这两张表并复核联动。
- 表格若使用真正的 AutoCAD TABLE 对象、属性块或 OLE 表格，文字枚举取不到内容，
  需先在 CAD 里炸开（EXPLODE）成 TEXT。
- 物料描述变更（施工/竣工名称不同）会按「竣工独有 + 施工多余」列出，
  需要人工判断是否为同一物料改名，脚本不做模糊匹配。
- 成品文件常含人工插入/合并的行、或取自另一版次的数量（NC25D007 即如此）。
  技能按图纸原始数据生成，差异项在核对报告中按分组列出；不要用成品差异
  反推解析参数，交付前需人工复核后再用于结算。
- 本机实测 2.4 MB 级别的复杂 DWG（如 NC26E085）用浩辰 COM 读取会超过数分钟甚至卡住，
  属 CAD/图纸复杂度问题而非解析逻辑；建议每批只读 2~3 张并用 `--cache-dir` 缓存，
  或先用 CAD 另存为简化版本。
